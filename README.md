# Home Hariki — app home page, privacy policy, terms

Public, login-free site for **Home Hariki**, the private Home Assistant instance operated by
Victor Seiji Hariki. The same Google OAuth application (`home-hariki`) is also the private
integration used by his other self-hosted tools (n8n workflows and similar) — Google is only
ever involved when a user connects their *own* Google account to an optional feature inside one
of those tools. Google is never used to sign in. It exists to satisfy the Google Cloud OAuth branding requirements for
project `home-hariki`: a public app home page that displays the app name and logo and links to a
privacy policy and terms of service on the same domain.

- `index.html` — app home page: name, logo, what the app is, sign-in link, policy links
- `privacy.html` — privacy policy (consent screen: *Application privacy policy link*)
- `terms.html` — terms of service (consent screen: *Application terms of service link*)
- `style.css` — shared styling, light and dark
- `logo.png` (512), `logo-120.png` (120), `favicon.png` (64) — generated by
  `tools/make_logo.py`, **RGBA with transparent corners** so the rounded tile works on any
  background
- `logo-120-solid.png` (120) — same mark, fully opaque edge to edge: the file to upload to the
  OAuth consent screen, which renders the logo on a white card
- `tools/rename-brand.sh` — one-shot rename if the consent-screen app name changes

Consent screen (`Google Auth Platform → Branding`, project `home-hariki`):

```
App name         : Home Assistant      (see "Branding" note below)
Home page        : https://legal.seijihariki.com/
Privacy policy   : https://legal.seijihariki.com/privacy.html
Terms of service : https://legal.seijihariki.com/terms.html
App logo         : logo-120-solid.png  (120x120 opaque PNG, <1MB)

## Branding note

The consent screen's app name is `Home Assistant`, so the home page shows that name (the
instance is called *Home Hariki*). "Home Assistant" is a Nabu Casa trademark: if Google objects
during branding verification, rename the app (e.g. `Home Hariki`) and run
`tools/rename-brand.sh "Home Assistant" "Home Hariki"`.


## Public URLs

```
https://legal.seijihariki.com/
https://legal.seijihariki.com/privacy.html
https://legal.seijihariki.com/terms.html
```

GitHub default hostnames still work as an alias:

```
https://seijihariki.github.io/legal/
https://seijihariki.github.io/legal/privacy.html
https://seijihariki.github.io/legal/terms.html
```

The `CNAME` file pins the custom domain. DNS: Cloudflare zone `seijihariki.com`,
`legal` CNAME → `seijihariki.github.io`, **DNS only** (not proxied) so GitHub Pages
terminates TLS with its own Let's Encrypt certificate.

## Editing

Edit the HTML directly, update the `Last updated` line in the changed page, commit and push.
GitHub Pages redeploys automatically on push to `main`. No build step.

Regenerate the logo with `python3 tools/make_logo.py .` (pure Python, no dependencies; writes the
512/120/64 px transparent files plus the opaque 120 px consent-screen file). Asset URLs carry a
`?v=N` query because GitHub Pages serves assets with `max-age=600` — bump it when the logo or CSS
changes, otherwise browsers keep showing the old logo for up to ten minutes.

Content must stay honest about what the Services are: personal, self-hosted, invitation-only,
non-commercial, no advertising and no data resale.
